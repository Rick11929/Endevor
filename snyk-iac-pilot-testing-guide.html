Pilot Testing Guide

Snyk Infrastructure as Code (IaC) — CLI & IDE Pilot

Step-by-step configuration and validation guide for piloting snyk iac test via the Snyk CLI and IDE plugins (VS Code & JetBrains). Because SSO is not available on the internal network, all authentication uses a Personal Access Token (PAT).

Scope: CLI testing + IDE testing only (no CI/CD, no SCM integration) Auth: Personal Access Token (PAT) Version: 1.0 — August 2026

Intro1. Scope, Objectives & Prerequisites

1.1 Pilot objectives

  • Validate that Snyk IaC scanning detects misconfigurations in Terraform, Kubernetes YAML, CloudFormation, and ARM files.
  • Verify the developer workflow in the CLI (ad-hoc and pre-commit scanning) and in the IDE (inline, on-save scanning).
  • Confirm that PAT-based authentication works end-to-end on the internal network without SSO/OAuth browser flows.
  • Confirm network reachability to Snyk endpoints through the corporate proxy/firewall.

1.2 Out of scope

  • CI/CD pipeline integration, SCM (Git repository) integration, Snyk Broker, Snyk Code / Snyk Open Source / Snyk Container testing, and custom Rego rules.

1.3 Prerequisites

Phase 02. Account Setup & PAT Generation

Step 0.1 — Confirm the Snyk region / endpoint

  1. Log in to the Snyk Web UI (for example https://app.snyk.io) and confirm which region your tenant is hosted in (SNYK-US-01, SNYK-US-02, SNYK-EU-01, or SNYK-AU-01).
  2. If your tenant is not on the default SNYK-US-01 endpoint, record the region name — the CLI must be pointed at it before authentication (Step 1.2).
Official doc: Authenticate to use the CLI — Prerequisites (environment config)

Step 0.2 — Generate a Personal Access Token (PAT)

  1. Log in to the Snyk Web UI and open your personal account settings.
  2. In the sidebar, navigate to Personal Access Tokens.
  3. Complete the form and click Generate new token.
  4. Copy the token immediately and store it in the corporate secrets vault. It cannot be viewed again later and must never be committed to source control.
  5. Distribute one PAT per pilot participant (personal tokens) rather than sharing a single token, so activity is attributable per user.
Official doc: Getting started — Obtain and use your token (Personal Access Tokens)
Authentication for API — How to obtain your personal access token
Important: Snyk states that PAT authentication is progressively rolled out to Enterprise customers. If the Personal Access Tokens page is not visible in your account settings, contact your Snyk account team / Snyk Support to enable it. As a fallback, the legacy API token (Account settings → General → API Token → "click to show") works with the exact same CLI and IDE steps below — everywhere this guide says "PAT", the legacy API token can be substituted.

Phase 13. CLI Track — Install, Authenticate, Scan

Step 1.1 — Install the Snyk CLI

  1. Install using npm (requires Node.js): 
    npm install -g snyk
    …or use the standalone executable / Scoop / Homebrew methods listed in the official install page. On a locked-down intranet, download the standalone binary and distribute it through your internal artifact repository.
  2. Verify the installation: 
    snyk --version
  3. Use CLI version 1.939.0 or later to get the current IaC test output format, and note that from CLI v1.594.0 onward, IaC configuration files are processed locally and do not leave the machine.
Official doc: Install or update the Snyk CLI
Understand the IaC CLI test results (version notes)

Step 1.2 — (Only if non-default region) Point the CLI at your environment

  1. If your tenant is on SNYK-US-02, SNYK-EU-01, or SNYK-AU-01, run before authenticating: 
    snyk config environment SNYK-EU-01   # example
  2. Skip this step entirely if you are on the default SNYK-US-01 endpoint.
Official doc: Authenticate to use the CLI — Prerequisites

Step 1.3 — Authenticate with the PAT (no browser / no SSO)

Choose one of the following three officially supported, browser-free methods. Method A is recommended for pilot desktops.

Method A — Persist the PAT in the local CLI profile

snyk auth <YOUR_PAT>

Or equivalently via the config command:

snyk config set api=<YOUR_PAT>

Method B — Environment variable (recommended for shared/CI-like shells)

# Linux / macOS
export SNYK_TOKEN=<YOUR_PAT>

# Windows (PowerShell)
$env:SNYK_TOKEN="<YOUR_PAT>"

# Windows (persist for the user)
setx SNYK_TOKEN "<YOUR_PAT>"

SNYK_TOKEN overrides any token stored in the local CLI configuration (~/.config/configstore/snyk.json).

Method C — One-shot per command

SNYK_TOKEN=<YOUR_PAT> snyk iac test main.tf

Verify authentication

snyk config get api        # should return your token (method A)
snyk iac test --help       # should run without an auth error
Official doc: Authenticate to use the CLI — Personal Access Token (PAT)
snyk auth command reference
Configure the Snyk CLI to connect to the Snyk API — SNYK_TOKEN

Step 1.4 — (Intranet) Configure the corporate proxy

  1. Set the proxy environment variables before running the CLI: 
    export HTTPS_PROXY=http://proxy.corp.example:8080
export HTTP_PROXY=http://proxy.corp.example:8080
export NO_PROXY=localhost,127.0.0.1,.corp.example
  2. If the corporate proxy performs TLS inspection (MITM), make the proxy's root CA available to Node.js, for example: 
    export NODE_EXTRA_CA_CERTS=/path/to/corp-root-ca.pem
  3. If the proxy demands authentication you cannot satisfy, test with the --proxy-noauth flag.
Official doc: Proxy configuration for Snyk CLI
Environment variables for Snyk CLI
Troubleshoot certificate errors (NODE_EXTRA_CA_CERTS)

Step 1.5 — Pin the pilot Organization

  1. Decide which Snyk Organization owns the pilot results (rule severities are controlled per-Organization).
  2. Set it once so it does not need to be repeated: 
    snyk config set org=<ORG_SLUG_OR_ID>
Official doc: Test your IaC files — Target a specific Snyk Organization

Step 1.6 — Run IaC scans

  1. Scan everything under the current directory (recursive): 
    cd /path/to/iac-repo
snyk iac test
  2. Scan specific files (paths must be under the current working directory): 
    snyk iac test main.tf modules/network.tf
  3. Scan a directory, limiting traversal depth: 
    snyk iac test terraform/ --detection-depth=3
  4. Filter by severity: 
    snyk iac test --severity-threshold=medium
  5. Scan a Terraform plan: 
    terraform plan -out=tfplan.binary
terraform show -json tfplan.binary > tf-plan.json
snyk iac test tf-plan.json
  6. Export machine-readable results: 
    snyk iac test --json > results.json
snyk iac test --sarif-file-output=snyk-iac.sarif
  7. (Optional) Send a one-time snapshot to the Snyk Web UI — there is no snyk monitor equivalent for IaC, so use --report: 
    snyk iac test --report
Official doc: Snyk CLI for IaC
Test your IaC files
snyk iac test command reference

Step 1.7 — Interpret the results

  1. Each finding lists: severity, issue title, description (Info), the rule URL (https://security.snyk.io/rules/cloud/...), the resource path, the file, and the remediation hint (Resolve).
  2. The summary block shows files with/without issues, ignored issues, and a severity breakdown.
  3. Exit codes: 0 = no issues found, 1 = issues found, 2 = failure/error. A non-zero exit on findings is expected behavior — wrap accordingly in scripts.
Official doc: Understand the IaC CLI test results
CLI track exit criteria: PAT auth succeeds without a browser; snyk iac test completes through the corporate proxy; findings are reported for the intentionally insecure sample files; JSON/SARIF export works.

Phase 24. IDE Track — VS Code & JetBrains

4.A — Visual Studio Code

Step 2A.1 — Install the Snyk extension

  1. Install Snyk Security from the VS Code Marketplace (if the Marketplace is blocked on the intranet, download the .vsix and install via Extensions → … → Install from VSIX).
  2. On first run the extension automatically downloads the Snyk CLI (which embeds the Snyk Language Server). If outbound download is blocked, disable Automatic Dependency Management in the Snyk settings and set CLI Path to the internally distributed binary from Step 1.1.
Official doc: Visual Studio Code extension — install & setup
VS Code extension configuration, environment variables, and proxy

Step 2A.2 — Authenticate with PAT (no browser / no SSO)

  1. Click the Snyk icon in the Activity Bar, then the Settings (gear) icon.
  2. Find Authentication Method and change it to Personal Access Token.
  3. Open the Command Palette (Ctrl+Shift+P), run Snyk: Set Token, and paste your PAT.
  4. If you use the legacy API token instead, set Authentication Method to Token authentication and use the same Snyk: Set Token command — do not click "Connect & Trust Workspace" (that path opens a browser flow).
Official doc: Authentication for the Visual Studio Code extension — PAT steps

Step 2A.3 — Enable and configure IaC scanning

  1. In Snyk settings → Scan configuration, confirm Snyk IaC is enabled (it is enabled by default) — it scans Terraform and Kubernetes (and other supported) configuration files.
  2. Set Scanning mode to auto so scans run on file save and on project open.
  3. (Optional) Set the Organization to the pilot Org (use the ORG_ID) so results match the CLI configuration from Step 1.5.
  4. (Intranet) Configure the proxy via VS Code's Application → Proxy settings or the http_proxy/https_proxy environment variables; for TLS-inspection proxies set NODE_EXTRA_CA_CERTS and restart VS Code.
  5. Open the sample IaC repository, trust the folder when prompted, save a file, and confirm that issues appear inline and in the Snyk panel.
Official doc: VS Code extension — Scan configuration (Snyk IaC), proxy, environment variables
Troubleshooting for the VS Code extension (CLI download, logs)

4.B — JetBrains IDEs (IntelliJ IDEA, PyCharm, WebStorm, …)

Step 2B.1 — Install the Snyk plugin

  1. Install Snyk from Settings → Plugins → Marketplace (or install from disk if the Marketplace is unreachable).
  2. The plugin auto-downloads the CLI. On a restricted network, uncheck Automatically manage needed binaries and set Path to Snyk CLI to the internal binary from Step 1.1.
Official doc: Configuration for the Snyk JetBrains plugin and IDE proxy (executable settings)

Step 2B.2 — Authenticate with PAT (no browser / no SSO)

  1. Navigate to Settings → Tools → Snyk.
  2. Set Authentication Method to Use Personal Access Token.
  3. Click Connect IDE to Snyk.
  4. Paste the PAT into the Token field.
  5. Click Apply and Close. Analysis starts automatically.
Official doc: Authentication for the JetBrains plugin — PAT steps

Step 2B.3 — Enable and configure IaC scanning

  1. In Settings → Tools → Snyk, confirm Snyk IaC is enabled (enabled by default).
  2. Enable Scan automatically on start-up and save.
  3. (Optional) Set Organization to the pilot ORG_ID to align with the CLI track.
  4. (Intranet) The JetBrains plugin uses the IDE's proxy settings, but the underlying CLI does not — set both the IDE proxy and the HTTPS_PROXY/HTTP_PROXY environment variables for the IDE process.
  5. Open the sample IaC project, trust it when prompted, and verify findings appear in the Snyk tool window for Terraform/Kubernetes files.
Official doc: JetBrains plugin configuration (Snyk IaC toggle, proxy)
How to set environment variables by OS for IDEs and CLI
IDE track exit criteria: PAT authentication succeeds without any browser/SSO interaction in both VS Code and JetBrains; IaC findings appear inline for the sample files; scans trigger on save; CLI fallback (internal binary path) works when the plugin cannot download the CLI.

Net6. Intranet / Network Considerations

  • Allowlist: permit outbound HTTPS to *.snyk.io (API, downloads, and IaC rules endpoints) on the proxy/firewall for pilot machines.
  • Proxy: set HTTP_PROXY, HTTPS_PROXY, and NO_PROXY for the CLI; configure the IDE proxy separately for JetBrains (the plugin does not read the CLI's variables, and vice versa).
  • TLS inspection: if the corporate proxy intercepts TLS, distribute the root CA and set NODE_EXTRA_CA_CERTS (CLI + VS Code). "Allow unknown CA" / --insecure should be used only temporarily for troubleshooting.
  • CLI distribution: if downloads.snyk.io is unreachable, distribute the standalone CLI binary internally and point IDE plugins at it via their CLI path settings (disable automatic dependency management).
  • Regional endpoint: if the tenant is not on the default region, run snyk config environment <REGION> before authentication, and set the matching endpoint in IDE settings if required.
