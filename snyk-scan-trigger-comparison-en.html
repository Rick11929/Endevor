Focus: Snyk Code (SAST) · Research date: 2026-07-31 · Sources: Snyk official docs, Snyk Support knowledge base, and community discussions (numbered references at the bottom)

Key Takeaways

  • For multi-branch scanning, choose the CLI. It is the most mature path, validated by both official docs and community practice: check out a branch, scan, and group with --target-reference, or schedule per-branch CI runs. SCM branch monitoring is still behind a Closed Beta.[1][8][9]
  • The CLI is the only way to scan manually uploaded code. Neither the Web UI nor the API accepts direct source-package uploads — everything must hang off an SCM repository. For strict no-upload policies, consider Snyk Code Local Engine (self-hosted, code never leaves your network, still CLI-triggered).[2][12]
  • The full snippet + data-flow experience always ends in the Web UI. SCM imports get it natively; CLI scans need --report or snyk-to-html to fill the gap; the API is for pulling data into your own systems, not for interactive auditing.[15][16]
