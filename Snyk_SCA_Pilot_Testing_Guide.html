1. Pilot scope and objectives

This pilot evaluates Snyk Open Source (SCA) — detection of known vulnerabilities and license issues in third-party dependencies. The goal is to confirm that testers can authenticate with a PAT, prepare a project so that Snyk can resolve its complete dependency tree, and successfully trigger a scan both from the CLI and from an IDE.

In scopeOut of scope
  • Snyk CLI: install, PAT authentication, snyk test, snyk monitor
  • IDE plugins: Visual Studio Code and JetBrains (IntelliJ IDEA, WebStorm, PyCharm, etc.)
  • Open-source dependency scanning (SCA) only
  • Snyk Code (SAST), Container, IaC, Secrets
  • SCM (Git repository) integrations and PR checks
  • CI/CD pipeline integration
  • SSO / OAuth browser-based login (not available on the internal network)

2. Prerequisites

P1Snyk account and Organization

  • Each tester needs a Snyk account assigned to the pilot Organization (Enterprise plan recommended for PAT support).
  • PAT availability note: according to Snyk documentation, Personal Access Token authentication is progressively rolled out to Enterprise customers. If the Personal Access Tokens page is not visible in your account settings, ask the Snyk account team to enable it. If PAT cannot be enabled in time, fall back to the legacy personal API token — the CLI and IDE configuration commands below are identical for both token types.
Official link — Obtain a PAT / API token: https://docs.snyk.io/getting-started-guides/getting-started (section “Obtain and use your Snyk API token”)

P2Network access (internal network / proxy)

Because the pilot runs on an internal network without SSO, confirm the following before starting:

  • Outbound HTTPS (443) to app.snyk.io and api.snyk.io (or your regional endpoint such as api.eu.snyk.io) must be allowed through the firewall/proxy.
  • Outbound HTTPS to downloads.snyk.io is required if the IDE plugin should auto-download the Snyk CLI binary. If this is blocked, install the CLI manually first (Phase 1) and point the IDE plugin to it.
  • If your proxy uses a self-signed/internal CA certificate, the Snyk CLI supports an --insecure option and the IDE plugins expose an “Insecure (skip SSL verification)” setting. Use only when connecting through your internal CA.
  • Standard proxy environment variables (HTTPS_PROXY / HTTP_PROXY) are honored by the CLI.
Official link — VS Code extension configuration, environment variables and proxy: https://docs.snyk.io/developer-tools/integrations/snyk-ide-plugins-and-extensions/visual-studio-code-extension/visual-studio-code-extension-configuration-environment-variables-and-proxy
Official link — Unified IDE Configuration Dialog (Setup tab: endpoint, insecure, CLI path): https://docs.snyk.io/developer-tools/integrations/snyk-ide-plugins-and-extensions/unified-ide-configuration-dialog

P3Package managers installed and on PATH

Snyk CLI is a build-time tool: for SCA it invokes the project’s own package manager to build the dependency tree. Per the official “Getting started with the Snyk CLI” page: “Before you can use the CLI for Open Source scanning, you must install your package manager. The needed third-party tools, such as Gradle or Maven, must be in the PATH.”

  • Node.js + npm (or Yarn / pnpm) for JavaScript projects
  • Java JDK + Maven (mvn) or Gradle (gradle/wrapper) for JVM projects
  • Python (python/python3 + pip) for Python projects
  • .NET SDK (dotnet) for C# projects
  • Go toolchain for Go Modules projects
Official link — Getting started with the Snyk CLI: https://docs.snyk.io/developer-tools/snyk-cli/snyk-cli/getting-started-with-the-snyk-cli

P4Pilot test project

  • Prepare one sample repository per technology stack used in your organization (e.g., one Maven project and one npm project).
  • The project must contain a supported manifest file at the repository root or in subfolders (see Section 3).
  • The project must be able to resolve/download all of its dependencies from the pilot machine — including access to your internal artifact repository (Artifactory/Nexus mirrors) if public registries are blocked.
Official link — Supported languages, package managers, and frameworks: https://docs.snyk.io/supported-languages/supported-languages-package-managers-and-frameworks

3. Key concept: Snyk SCA requires full dependency resolution

Critical — read before scanning Snyk Open Source does not merely grep manifest files. snyk test identifies all local dependencies — direct and transitive — by building the full dependency tree, then queries the Snyk vulnerability database for every package in that tree. If the tree cannot be fully built (missing lockfile, package manager not installed, unreachable artifact repository, failed build/restore), the scan will either fail outright or silently under-report transitive vulnerabilities. The single most common pilot failure is scanning a project whose dependencies are not resolvable on the pilot machine.
Official link — Snyk CLI for Open Source (how the dependency tree is built, manifest auto-detection): https://docs.snyk.io/developer-tools/snyk-cli/snyk-cli/scan-and-maintain-projects-using-the-cli/snyk-cli-for-open-source

3.1 What “full resolution” means per ecosystem

Use this table to prepare each pilot project before triggering a scan. Rule of thumb: if <package manager> install/restore succeeds on the machine, Snyk can scan the project.

Ecosystem Manifest file(s) Snyk detects Pre-scan requirements on the pilot machine
npm / Yarn / pnpm package.json + package-lock.json, yarn.lock, or pnpm-lock.yaml Commit the lockfile — Snyk builds the tree from it. Keep the lockfile in sync with package.json (out-of-sync lockfiles cause failures or wrong results). Node.js/npm must be installed; run npm install first if in doubt.
Maven pom.xml mvn must be on PATH. Snyk executes Maven to produce the dependency list, so mvn dependency:tree (or a normal build) must succeed — all repositories in settings.xml, including internal mirrors, must be reachable. Test-scope (dev) dependencies are ignored by default; add --dev to include them.
Gradle build.gradle, build.gradle.kts (Kotlin DSL: CLI only) Gradle (or the wrapper) must be on PATH and the dependency resolution task must succeed. Without a committed gradle.lockfile, Snyk officially recommends the CLI/IDE workflow — otherwise the full dependency tree may not be apparent and results will be incomplete.
Python (pip) requirements.txt (also Poetry pyproject.toml/poetry.lock, Pipenv Pipfile) Snyk uses Python on the machine to find dependencies, so packages should be installed/resolvable in the environment, and the Python version affects the tree. Use --command=python3 if needed, and --skip-unresolved for packages that exist only in a private index Snyk cannot reach. Non-default manifest names require --file=<name> --package-manager=pip.
.NET (NuGet) *.csproj/*.sln, obj/project.assets.json, packages.config The dotnet SDK must be installed and dotnet restore must succeed — Snyk uses the build system to determine installed dependencies (there is no package-lock.json equivalent). All PackageReference entries need a version attribute. A runtime SDK matching the target framework gives the most accurate tree.
Go Modules go.mod The Go toolchain must be available so the module graph can be resolved; internal module proxies (GOPROXY) must be configured if public proxy access is blocked.
Official links — Supported languages list: https://docs.snyk.io/supported-languages/supported-languages-list · JavaScript: https://docs.snyk.io/supported-languages/supported-languages-list/javascript · Java & Kotlin: https://docs.snyk.io/supported-languages/supported-languages-list/java-and-kotlin · Best practices for Java and Kotlin (Gradle lockfile guidance): https://docs.snyk.io/getting-started/supported-languages-and-frameworks/java-and-kotlin/best-practices-for-java-and-kotlin · Python: https://docs.snyk.io/supported-languages/supported-languages-list/python · .NET: https://docs.snyk.io/supported-languages/supported-languages-list/.net

3.2 Pre-flight checklist — run before every scan

  • A supported manifest file exists in the folder you are about to scan.
  • Lockfiles are committed and in sync with the manifest (npm/Yarn/pnpm, and Gradle where applicable).
  • The package manager is on PATH and its resolution command succeeds on this machine (e.g. npm install, mvn -q dependency:tree, gradle dependencies, pip install -r requirements.txt, dotnet restore).
  • All dependency sources resolve — internal artifact mirrors are configured and reachable.
  • If a scan fails, re-run with -d to capture debug logs before escalating.

4. Phase 1 — CLI pilot (step by step)

1Create a Personal Access Token (PAT)

  1. Log in to the Snyk Web UI and open your personal account settings.
  2. In the sidebar, select Personal Access Tokens.
  3. Complete the form and click Generate new token.
  4. Copy the token immediately and store it securely — it cannot be viewed again.
NoteIf the Personal Access Tokens page is not available for your Organization yet (progressive Enterprise rollout), use the legacy personal API token instead: Account Settings → General → API Token → click to show. All commands below accept either token. Do not use a Service Account token for IDE/CLI interactive testing — Snyk documents unexpected behavior for that combination.
Official link — Obtain and use your Snyk API token / PAT: https://docs.snyk.io/getting-started-guides/getting-started

2Install the Snyk CLI

Pick one method (standalone binary is usually simplest behind a corporate proxy):

# npm (requires Node.js)
npm install snyk -g

# Windows (Scoop)
scoop bucket add snyk https://github.com/snyk/scoop-snyk
scoop install snyk

# macOS/Linux (Homebrew)
brew tap snyk/tap && brew install snyk

# Standalone binary — Windows
# Download snyk-win.exe, rename to snyk.exe, move to C:\tools\snyk\, add to PATH
curl https://static.snyk.io/cli/latest/snyk-win.exe -o snyk.exe

# Standalone binary — Linux/macOS example
curl --compressed https://downloads.snyk.io/cli/stable/snyk-linux -o snyk
chmod +x ./snyk && sudo mv ./snyk /usr/local/bin/

Verify the installation:

snyk --version
Official link — Install the Snyk CLI: https://docs.snyk.io/developer-tools/snyk-cli/snyk-cli/install-the-snyk-cli

3Authenticate with the PAT (no browser, no SSO)

  1. (Regional tenants only) If your Organization is hosted outside SNYK-US-01 (e.g. SNYK-EU-01, SNYK-US-02, SNYK-AU-01), set the environment first: 
    snyk config environment SNYK-EU-01
  2. Authenticate with the PAT — this is fully headless and needs no browser: 
    snyk auth <YOUR_PAT>
    Expected result: Your account has been authenticated.
  3. Alternative, equivalent methods (use whichever your security policy prefers): 
    # Persist via config
snyk config set api=<YOUR_PAT>

# Or via environment variable (recommended for shared/temporary shells)
export SNYK_TOKEN=<YOUR_PAT>          # Linux/macOS
setx SNYK_TOKEN "<YOUR_PAT>"            # Windows (new shells)
  4. Sanity check connectivity and auth: 
    snyk test --help
Official link — Authenticate to use the CLI (PAT / token / env var / regional environments): https://docs.snyk.io/developer-tools/snyk-cli/authenticate-to-use-the-cli

4Prepare the project for a complete scan

  1. Clone/copy the pilot project onto the machine and open a terminal at the folder that contains the manifest file.
  2. Run the ecosystem’s own resolution command and make sure it succeeds (see Section 3.1). Example for Maven: 
    mvn -q dependency:tree        # must complete without errors
    Example for npm: 
    npm install                   # ensures lockfile is in sync
  3. Only proceed when the package manager itself can fully resolve dependencies on this machine.
Official link — Snyk CLI for Open Source (manifest auto-detection list): https://docs.snyk.io/developer-tools/snyk-cli/snyk-cli/scan-and-maintain-projects-using-the-cli/snyk-cli-for-open-source

5Trigger the scan — snyk test

cd /path/to/pilot-project
snyk test

Useful options during the pilot:

snyk test --all-projects            # scan every manifest in the repo (monorepos)
snyk test --file=pom.xml            # target a specific manifest
snyk test --org=<ORG_ID>            # report against the pilot Organization
snyk test --severity-threshold=high # only show high/critical issues
snyk test --json                    # machine-readable output for evidence capture
snyk test -d                        # debug output (attach this when reporting issues)

Interpret the exit code: 0 = scan completed, no vulnerabilities · 1 = scan completed, vulnerabilities found · 2 = failure, re-run with -d · 3 = no supported project detected (go back to Step 4).

Success signalThe CLI prints the dependency tree analysis (“Tested N dependencies for known issues…”) and an issue list with severity, package paths (direct vs. transitive), and fix advice. Seeing “0 issues” is also a successful scan — verify the dependency count matches your expectation, otherwise the tree may have been truncated.
Official link — snyk test command reference: https://docs.snyk.io/developer-tools/snyk-cli/snyk-cli/commands/test

6(Optional) Publish results — snyk monitor

To create a continuously monitored Project snapshot in the Snyk Web UI:

snyk monitor --org=<ORG_ID> --project-name=<pilot-project-name>

Then log in to the Snyk Web UI and confirm the Project appears on the Projects page with the same dependency count. Re-run snyk monitor after dependency changes — it does not update automatically.

Official link — snyk monitor command reference: https://docs.snyk.io/developer-tools/snyk-cli/snyk-cli/commands/monitor
Security notice — code execution Because snyk test invokes the package manager (and may execute build logic, e.g. Gradle), only scan projects you trust. Review the official code execution warning referenced from the snyk test and monitor documentation pages before scanning third-party code.

5. Phase 2 — IDE pilot (step by step)

Both IDE plugins below scan SCA (Open Source) by default. Because OAuth/SSO browser login is unavailable on the internal network, every IDE must be switched to the “Personal Access Token” authentication method and given the PAT manually.

5.1 Visual Studio Code

1Install the extension

  1. Open VS Code → Extensions (Ctrl+Shift+X) → search “Snyk Security” → Install.
  2. By default the extension auto-downloads the Snyk CLI (requires access to downloads.snyk.io). If that host is blocked, open the Snyk settings and set CLI path to the binary installed in Phase 1, Step 2 (disable “Manage binaries automatically” if needed).
Official link — Unified IDE Configuration Dialog (CLI path, release channel, download base URL): https://docs.snyk.io/developer-tools/integrations/snyk-ide-plugins-and-extensions/unified-ide-configuration-dialog

2Switch authentication to PAT

  1. Click the Snyk icon in the Activity Bar → Settings (gear icon).
  2. Find Authentication Method and change it to Personal Access Token.
  3. Open the Command Palette (Ctrl+Shift+P) → run Snyk: Set Token → paste the PAT.
  4. (Regional tenants) set the Custom Endpoint to your region’s API URL; for https://api.snyk.io no configuration is required.
Official link — Authentication for the Visual Studio Code extension (PAT steps): https://docs.snyk.io/developer-tools/integrations/snyk-ide-plugins-and-extensions/visual-studio-code-extension/authentication-for-visual-studio-code-extension

3Open the project and trigger the SCA scan

  1. File → Open Folder → select the folder containing the manifest file (same preparation as CLI Step 4 — dependencies must be resolvable on this machine; the plugin runs the same Snyk CLI engine under the hood).
  2. When prompted, trust the workspace folder (Snyk only scans trusted folders).
  3. The analysis starts automatically. To run it manually: Snyk panel → rescan, or Command Palette → Snyk: Rescan.
  4. Confirm results appear under the Open Source Security tree in the Snyk panel, with direct/transitive paths and fix advice.
Success signalThe Snyk panel lists Open Source issues grouped by severity for the manifest(s) in the workspace, and the dependency count matches the CLI result from Phase 1, Step 5.

5.2 JetBrains IDEs (IntelliJ IDEA, WebStorm, PyCharm, etc.)

1Install the plugin

  1. Settings/Preferences → Plugins → Marketplace → search “Snyk Security” → Install → restart the IDE.
  2. The plugin bundles/downloads the Snyk CLI. If downloads.snyk.io is blocked, set CLI path in Settings → Tools → Snyk to the binary from Phase 1, Step 2.
Official link — Configuration for the Snyk JetBrains plugin and IDE proxy: https://docs.snyk.io/developer-tools/integrations/snyk-ide-plugins-and-extensions/jetbrains-plugin/configuration-for-the-snyk-jetbrains-plugin-and-ide-proxy

2Switch authentication to PAT

  1. Navigate to Settings → Tools → Snyk.
  2. Set the Authentication Method to Use Personal Access Token.
  3. Click the Connect IDE to Snyk button.
  4. Paste the PAT into the Token field.
  5. Click Apply and Close.
Official link — Authentication for the JetBrains plugin (PAT steps): https://docs.snyk.io/developer-tools/integrations/snyk-ide-plugins-and-extensions/jetbrains-plugin/authentication-for-the-jetbrains-plugins

3Open the project and trigger the SCA scan

  1. Open the pilot project (again: dependencies must be resolvable on this machine — for Maven/Gradle projects, ensure mvn/gradle is on PATH for the IDE process, and the internal repositories in settings.xml/build.gradle are reachable).
  2. Click the Snyk icon in the navigation bar → Trust project and scan.
  3. Verify the Snyk tool window shows Open Source Security results with severity grouping and remediation advice.
Success signalThe Snyk tool window populates Open Source Security findings for the project, matching the CLI scan results in count and severity distribution.

6. Pilot success criteria

A tester passes the pilot when all of the following are true:

  • PAT created (or legacy API token fallback documented) and stored securely.
  • snyk auth <PAT> succeeds headlessly on the internal network.
  • snyk test completes on at least one project per relevant ecosystem with exit code 0 or 1 (not 2/3).
  • The reported dependency count matches the package manager’s own tree (spot-check with mvn dependency:tree / npm ls / pip list).
  • Results include transitive (indirect) dependency paths — proof the full tree was built.
  • (Optional) snyk monitor creates a Project visible in the Snyk Web UI.
  • IDE plugin authenticates with the PAT and its Open Source Security results match the CLI results for the same project.
  • Any failure was captured with snyk test -d debug logs and reported to the pilot owner.

7. Troubleshooting

SymptomLikely cause & fix
Exit code 3 — “no supported projects detected” No supported manifest in the scanned folder. Run from the folder that contains the manifest, or pass --file=<manifest> (for pip also --package-manager=pip).
Scan fails or dependency count is far lower than expected Incomplete dependency resolution — missing lockfile, package manager not on PATH, or internal artifact repository unreachable. Reproduce with the package manager itself (Section 3.2 checklist), then re-run snyk test -d.
Gradle project: incomplete tree / missing transitive issues No committed gradle.lockfile. Use the CLI/IDE workflow (this pilot) rather than SCM import, and ensure the Gradle build resolves successfully on the machine.
Python: “package not found” / “no matching distribution” errors Wrong Python version or packages not installed. Use --command=python3, install the requirements first, and use --skip-unresolved for private packages Snyk cannot reach.
HTTP 401 / authentication errors Wrong or expired token, or wrong regional endpoint. Re-run snyk auth <PAT>; set snyk config environment <REGION> if not on SNYK-US-01.
SSL / certificate errors through the internal proxy Self-signed internal CA. Configure HTTPS_PROXY correctly; as a last resort use --insecure (CLI) or the IDE “Insecure (skip SSL verification)” setting — internal CA only.
IDE: no PAT option / PAT not accepted PAT is progressively rolled out to Enterprise organizations — ask the Snyk account team to enable it. Meanwhile, use the legacy API token authentication method; do not use Service Account tokens in the IDE.
IDE: CLI download fails downloads.snyk.io blocked. Install the CLI manually (Phase 1, Step 2) and set CLI path in the plugin settings.
Official link — Snyk Error Catalog (CLI/Open Source error codes and workarounds): https://docs.snyk.io/scan-with-snyk/error-catalog
